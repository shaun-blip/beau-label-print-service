# Designer changes, 16 November 2026

Eight changes from Shaun's review of the theme preview. Drawing code is untouched, so printed sheets are not affected and the print service does not need a redeploy.

## What changed

1. **Step 02 note.** "Every label prints the same." read as a rule. It now says "All N labels will match. Want each label different? Choose that under Choose your wording."
2. **Step 04 gaps.** The design grid had two full-width heading rows ("Made for Birthday", "Classics for any occasion"). Each left empty spaces after the last design of its group. The grid is now continuous. Designs made for the occasion carry a small star in the corner, and the count line above the grid explains it.
3. **Sheets question in step 05.** With two or more sheets and "Different on each label", the customer must now answer "You're ordering N sheets. Should they match?" The two answers say what each one means. Until it is answered, the box is highlighted with a "Choose one" tag, neither answer is selected, and the order is blocked with a message (`screen()` returns it, so `exportDesign().problem` carries it too). The first row of buttons also has a heading: "Should every label say the same thing?"
4. **Bundle box removed.** The "Build a bundle, unlock free wraps" box and its tier maths are gone from the wrap step. The page no longer mentions bundles.
5. **Lines on the bottle preview.** The "On a bottle" and "In a wrap" previews curve the label by drawing it in 22 narrow strips. On designs with a panel over a colored background, the lower color showed through at each strip edge as faint vertical lines. Each strip is now drawn as one layer (`photoScene()` in `js/02-drawing.js`), which removes them. Preview only: printed sheets never used the strips.
6. **A real wrap in the preview.** New function `showWrap({image, title})` (in `js/07-print-and-events.js`). Give it a wrap's main product photo and the "In a wrap" preview shows that wrap with the customer's label in its window; `showWrap(null)` returns to the sample. It works because the store's main photo of every wrap is shot the same way (one bottle, centred, on white). It finds the bottle in the photo, clears the white around it and places the label where it sits on our sample photo of that size. A photo that isn't like that (a lifestyle shot first, an unusual bottle) is refused: it resolves to `false` and the sample wrap stays. Checked 16 Nov against 119 main photos in three collections: 111 accepted, 8 refused because their first photo isn't on white. See CONNECT-WRAPS.md for where to call it.
7. **Changing bottle clears the chosen wraps.** Wraps are made for one bottle size. Picking a different bottle now empties `state.wraps`, drops any `showWrap` photo, and shows a note under the bottle choice and in the wrap step saying what was removed and why. The note goes when the next wrap is added.
8. **Stray grey bar on the bottle preview.** The dashed "Your name here" frame was measured wrongly inside the bottle previews and showed as grey bars (most visible on minis). On a bottle the placeholder words are now only faded; the dashed frame stays on the flat label view.

## How to apply to the theme

Files touched in this kit: `designer.html`, `designer.css`, `js/02-drawing.js`, `js/06-app.js`, `js/07-print-and-events.js`.

If the theme's copies of those files are unchanged from the kit apart from asset addresses, apply `tools/changes-2026-11-16.json`: it is a list of exact `find` / `replace` pairs, 28 in all, and each `find` occurs exactly once across those five files. If a `find` is missing, the theme copy was edited there: open the same spot in this kit's file and carry the change over by hand.

New state: `state.scopePicked`, `state.wrapsGone`, `wrapShot` (none exported, none needed by the print service). New helpers: `needScope()`, `showWrap()`. New CSS classes: `.star`, `.starkey`, `.ask`, `.ask-t`, `.ask-tag`, `.chips.two`. New element ids: `scopeask`, `scopeq`, `wrapgone`, `sizegone`.
