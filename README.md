# BeauBottles label print service

Turns a paid Shopify order for custom labels into print-ready PDFs and attaches them to the order.

## What it does

1. **Customer finishes a design** on the store. The designer page calls `exportDesign()` and posts the result to `POST /designs`. The service checks it (brand names, missing words), saves it and returns an `id`.
2. **The storefront adds the label product to the cart** with that id as a hidden line item property, `_design_id`.
3. **Shopify tells the service the order is paid** (`orders/paid` webhook → `POST /webhooks/orders-paid`).
4. **The service draws the sheets** with the same designer code in a headless browser, so the print matches what the customer saw, and makes one PDF per label line (one page per distinct sheet).
5. **The PDF lands on the order**: uploaded to Shopify Files, linked in the order note, saved in the order metafield `custom_labels.print_files`, and the order is tagged `labels-ready`. If anything goes wrong the order is tagged `labels-problem` with a note saying why.

The number of sheets printed comes from the line item quantity on the order, not from what the browser sent.

## Deploy on Render

1. Put this folder in a GitHub repository (private is fine).
2. In Render: **New → Blueprint**, choose the repository. `render.yaml` creates a Docker web service with a 1 GB disk at `/var/data` (saved designs live there; without the disk they vanish on every deploy).
3. Fill in the environment values:

| Name | Value |
|---|---|
| `SHOPIFY_SHOP` | `your-store.myshopify.com` |
| `SHOPIFY_CLIENT_ID` | Client ID of the app made in Shopify's Dev Dashboard (below) |
| `SHOPIFY_CLIENT_SECRET` | Client secret of the same app |
| `SHOPIFY_WEBHOOK_SECRET` | The secret Shopify signs webhooks with (below) |
| `ALLOWED_ORIGINS` | `https://www.beaubottles.com,https://beaubottles.com` |
| `ADMIN_KEY` | Generated by Render; needed for the test links |

4. Open `https://<service>.onrender.com/health`. It should answer `{"ok":true,...}`.

The starter plan matters: free Render services sleep, and a sleeping service can miss or time out on Shopify's webhook.

## Shopify setup

1. **App**: since January 2026 Shopify apps are made in the Dev Dashboard, not in the store admin. Shopify admin → Settings → Apps → Develop apps → Build apps in Dev Dashboard → Create app. In the app's version, select the access scopes `write_orders`, `read_orders` and `write_files`, release the version, and install the app on the store. Copy the Client ID and Client secret from the app's Settings into `SHOPIFY_CLIENT_ID` and `SHOPIFY_CLIENT_SECRET`. The service exchanges them for a 24-hour access token and renews it by itself. (An older app made in the store admin before 2026 has a permanent token: put it in `SHOPIFY_ADMIN_TOKEN` instead.)
2. **Webhook**: topic `orders/paid`, format JSON, URL `https://<service>.onrender.com/webhooks/orders-paid`.
   - Created in Settings → Notifications → Webhooks: the signing secret is shown on that page.
   - Created through the app's API or configuration: the signing secret is the app's Client secret.
   Put whichever applies in `SHOPIFY_WEBHOOK_SECRET`.
3. **Order access**: the service only reads orders through the webhook payload and writes back to the same order, so no extra "all orders" access is needed.

## Storefront side

```js
const design = exportDesign();               // from the designer page
if (design.problem) { /* show it, stop */ }
const r = await fetch("https://<service>.onrender.com/designs", {
  method: "POST", headers: { "Content-Type": "application/json" },
  body: JSON.stringify(design)
});
if (!r.ok) { /* 422 = the service refused it; show (await r.json()).error */ }
const { id, summary } = await r.json();

await fetch("/cart/add.js", {
  method: "POST", headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ items: [{
    id: VARIANT_ID_FOR_SIZE,                  // champagne / prosecco / mini variant
    quantity: design.qty,                     // sheets
    properties: { _design_id: id, Occasion: summary.Occasion, Design: summary.Design, Lettering: summary.Lettering }
  }]})
});
```

Properties starting with `_` are hidden from the customer at checkout; the others show in the cart and on the order.

## Test links

- `GET /designs/<id>.pdf?key=<ADMIN_KEY>` — the PDF for a saved design, without placing an order.
- `POST /render?key=<ADMIN_KEY>` with a design as the JSON body — a PDF straight back.

## Run locally

```
npm install
PUPPETEER_EXECUTABLE_PATH=/path/to/chrome ADMIN_KEY=testkey SHOPIFY_WEBHOOK_SECRET=whsecret PORT=3999 npm start
BASE=http://localhost:3999 ADMIN_KEY=testkey SHOPIFY_WEBHOOK_SECRET=whsecret npm test
```

PDFs from the test land in `test/out`. Without `SHOPIFY_SHOP` and the app's Client ID and secret, the Shopify step is skipped and logged.

## First live test

1. Deploy, check `/health`.
2. Save a design from the store page and open its test link. Compare with the on-screen preview.
3. Place a test order (Shopify's Bogus Gateway or a 100% discount code). Within a minute the order should carry the `labels-ready` tag, a note with the PDF link and the metafield.
4. Print on plain paper and hold it against a label sheet before using real stock.

## Keeping it in step with the designer

`public/designer.html` is a copy of the designer page. **Copy the new file over it whenever the designer changes**, or prints will not match what customers see. Fonts are bundled from `@fontsource` packages (`src/fonts.js`) so the service never depends on Google Fonts being reachable; a new lettering style in the designer needs its font package added to `package.json`.
